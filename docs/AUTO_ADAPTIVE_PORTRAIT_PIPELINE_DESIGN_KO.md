## 1. 목표와 절대 제약

1. 작품이 실제 사용 허가된 **2차원 회화·드로잉·판화·일러스트**만 취급. 액자·전시장 사진, 조각·3D, 사진·애니메이션은 이 평면 작품 모드에서 제외.
2. 기존 **30초 자동 교체**, **90일 작품별 재노출 금지**, 모바일 **세로형 우선(운영 목표 세로 70%, 가로 30%)**, 사용 가능한 저장공간 **최대 8GiB**, 최소 **1.5GiB 시스템 여유**를 유지.
3. 결제수단 등록 없이 운영. 리소스 사용량/서버별 이용 약관/요청 제한 감지 시 자동 감속 또는 중지. 유료 외부 이미지 생성·업스케일 API 사용 안 함.
4. 원본의 저작권/제공처 라이선스를 확인한 뒤 허용되는 범위 내에서만 다운로드·변형·전시. 현행 수집 엔진 기본 화이트리스트는 **CC0 / 퍼블릭 도메인**을 유지; 라이선스 불명·무단재배포·우회가 필요한 콘텐츠는 유예. 변형 자체도 해당 라이선스 조건을 만족해야 함.
5. **AI 아웃페인팅/창작적 누락부 채우기를 기본 비활성화**: 없는 원작 요소를 만들어 원본처럼 보이게 하지 않음. 변환 이미지에는 원본으로 돌아갈 수 있는 링크·출처·변환 배지를 제공.
6. **예비 검색 결과·변환 시도 수·저장되지 않은 파일 기록을 실제 태블릿 보유량으로 혼동하지 않기**.

## 2. 아키텍처: 수집 서버와 태블릿의 역할 분리

```text
[GitHub 10분 cron 등록; 실행 시각 비보장]
  └─ API 페이지 순회/재시도/출처·권리/작품형 검사
      └─ 실제 다운로드·디코딩·원본 SHA256 + 시각 유사성 검사
          └─ candidate/native/needs_adaptation/rejected 판정
              ├─ 누적 원본 작품 ID·원본 URL·검증 속성·처리 정책 기록
              ├─ 소량 샘플만 비용 한도 내 GitHub Actions 단기 업로드
              └─ GitHub Issue #2 보고 (신규 원본/변환 적합 예상/오류)
                         ↓ (읽기 전용 공개 매니페스트)
[갤럭시 탭 A7 앱 — 화면 활성 시]
  └─ 매니페스트 적합성·버전 검사 → 허용 도메인에서 이미지 재다운로드
      └─ 해시 재검사 → Android 로컬 변환 → 현장 렌더 검사
          ├─ 원본 JPEG와 파생본 캐싱(8GiB 한도, 1.5GiB 남김)
          ├─ 30초 전시 및 중복/90일 제한 DB 기록
          └─ 실패 시 마지막 검증 이미지/로컬 대체화면 표시
```

- 현재 기본 앱 v1.7.2와 연구용 브랜치 APK는 별개. **새 설계만 저장한다고 태블릿에 적용되지 않음**.
- GitHub 기록만으로는 바이너리를 영구 보관하지 못한다. 소스가 소멸하면 태블릿 재다운로드 불가. `asset_cached`는 Android에서 파일 해시/디코딩·저장 완료 후에만 true.
- 앱을 끄거나 화면이 꺼지면 전시/로컬 변환 반복을 지속한다는 보장 없음. OS WorkManager 최소 반복 간격 등의 시스템 제약도 별도 고려.

## 3. 이미지별 자동 의사결정 표

| 원본 상태 | 처리 방식 | 결과 장부 | 원작 보존/주의 |
|---|---|---|---|
| 원본부터 세로 화면 작품 채움 ≥75%, 충분한 실제 픽셀 | **ORIGINAL** 원본 그대로 | `native_eligible` | 원본 우선 |
| 2차원 세로 작품, 짧은 변 ≥600px이나 권장 해상도 미달 | **UPSCALE_LANCZOS**: CPU 기반 1.2~2.0배, 과도한 확대 차단 | `adapted_eligible`, `native_lowres` 기록 유지 | 업스케일은 세부 묘사의 사실성 증가가 아님 |
| 가로 작품, 중요한 구도 안전 판정 어려움 | **LANDSCAPE_FULL_BLUR_BACKDROP**: 전체 원작을 선명하게 보여주고 확대 복제·블러 배경으로 화면 채움 | `landscape_displayable`; **작품 자체 75% 면적 충족으로 오인하지 않음** | 기본값; 원작 요소 손실 없음 |
| 가로 작품, 중심 대상이 뚜렷하고 주변 소실 허용 가능한 시각 점수 임계 통과 | **FOCAL_CROP** 보수적 관심영역 확대; 전체 원본 보기 옵션 유지 | `adapted_eligible` + 상세 crop box | 크롭은 작품의 일부만 보여줌; 원작 전체 전시와 별도 |
| 매우 작은 해상도, OCR/워터마크/권리 불명, 지나친 손실 | **REJECT/QUARANTINE** | 검증 불합격 기록 | 무리한 증강으로 적격 수량 부풀리지 않음 |

**추가 기준:** 원본 픽셀이 `600×900`인 경우 2× 확대가 가능하더라도 `1200×1800` 자연 해상도 원본으로 간주하지 않음. 업스케일된 실제 텍스처 정확도는 별도 신뢰도/변환 이력으로 표시. 600px 미만도 즉시 무조건 폐기할지는 실제 샘플/화질 실측으로 정한다.

## 4. 세로 화면 전시 변환기 (무인 기본값)

### 4.1 원본 손상 없는 배경 합성
- 원본 가로 비율을 유지하여 중앙에 온전히 표시. 원본의 확대 복사본을 화면 뒤에 배치한 뒤 강한 가우시안 블러/어둡게 처리.
- 배경 합성 면적을 원본 작품이 채운 실제 면적으로 계산하지 않음. 세로 화면의 75% 작품 면적을 요구하면 이 방식은 **전시 가능 가로형 별도 슬롯**으로 분류.
- 이미지 색, 투명도, EXIF 회전, 색 프로파일, 큰 이미지 메모리 사용량 검사. 워터마크 삭제·재현은 금지.

### 4.2 관심영역 크롭(선택적, 엄격)
- OpenCV CPU 기반 소프트웨어에서 에지/대비/살리언시와 중앙 가중치를 종합하여 후보 `crop_box=[x,y,w,h]` 생성. 사람 얼굴만 맹목적으로 우선하지 않음.
- 주변부에 인물/서명/중요 피사체가 있을 수 있으므로 **불확실성 점수가 높으면 전체 원본 방식으로 강제 복귀**.
- 최소 표시 비율/픽셀, 비율 75% 충족, 원본 요소가 너무 많이 삭제되는지, 잘림 금지 영역, 원본과 유사성을 독립 검사. 기준 미달 또는 판단 불가이면 가로 원본+배경 합성.
- 크롭 변환본과 원본은 **같은 artwork_key**를 공유. 두 컷을 서로 다른 작품 두 점으로 세지 않음.

### 4.3 업스케일
- 1차 구현은 무료 Pillow/Lanczos + 적절한 샤픈/노이즈 억제만 허용. CPU 제한과 메모리를 테스트하고 미세한 선/서명이 망가지는 이미지에는 적용하지 않음.
- 2차 AI 초해상도(Real-ESRGAN 등)는 입력 이미지에 없던 디테일을 생성할 수 있으므로 성능·라이선스·추론시간·미술 이미지 왜곡의 별도 실제 시험 통과 전에는 도입 안 함.
- 변환본 `derived_sha256`과 원본 `original_sha256`을 따로 보관하고 원본 파일의 바이트는 임의 덮어쓰지 않음.

## 5. 권리·작품 식별·중복 방지

1. ID `artwork_key = sha256(provider_id + ":" + provider_artwork_id)`; 기관이 다르게 재게시한 동일 작품은 원본 SHA256, 지각 해시(dHash/pHash), 제목/작가/연도 등으로 교차 중복 후보 식별. 완전한 동형작품 보장 아님.
2. 각 변환본 `variant_key = artwork_key + ":" + transform_type + ":" + transform_version`. 시청 90일 중복 판단 키는 **variant가 아니라 artwork_key**.
3. CC0/퍼블릭 도메인 여부를 원본 기관 기록과 공개 재사용 조건으로 증빙. CC BY 등 추가 지원은 원본/변형 전시 크레딧 및 라이선스 의무 구현을 먼저 시험한 뒤 열기.
4. 원본 URL이 삭제/403/이용조건 변경되면 적격 목록에서 제외 또는 `stale_source` 보류. 90일 미재사용 상태와 다운로드 상태는 독립.

## 6. 장부 필드와 수량 정의

매 원본 ID에 다음을 기록:
```json
{
  "artwork_key": "...",
  "provider": "Cleveland Museum of Art",
  "provider_artwork_id": "...",
  "source_url": "https://...",
  "license": "CC0",
  "license_checked_utc": "...",
  "source_sha256": "...",
  "verified_raw_pixels": [1200, 1800],
  "native_eligible": true,
  "display_mode": "ORIGINAL",
  "display_variant_sha256": "...",
  "upscale_factor": 1.0,
  "crop_box_original_pixels": null,
  "preserves_full_artwork": true,
  "displayed_artwork_area_ratio": 0.90,
  "adapted_eligible": false,
  "source_available_last_checked": "...",
  "stored_on_tablet": false,
  "tablet_file_sha256": null,
  "last_shown_utc": null,
  "status": "REMOTE_VERIFIED_NOT_CACHED"
}
```

회차 보고에 **별도의 다섯 수치**를 제공:
- `discovered_candidates`: 검색 결과(실제 수집 점수에 포함 금지).
- `new_originals_verified`: 원본 파일이 실제 다운로드·디코딩·권리/고유성 검사 통과한 원본 작품 수.
- `new_native_displayable`: 원본 자체가 전시 기준 통과.
- `new_adapted_displayable`: 원본 그대로는 불합격이었으나 파생본 실제 재검증 통과; 별도 unique artwork ID 기준.
- `tablet_cached_validated`: 태블릿에서 실물 바이트/해시를 저장·재오픈한 개수(서버 검증과 구분).

`total_unique_displayable = distinct(artwork_key where native OR adapted displayable)`. 변환 2개 생성했다고 **작품 2점 추가 금지**. 기준 736점과 최초 675점의 차이 61점은 검증 전까지 별도 주석 유지.

## 7. 10분 자동 실행과 결손 감시

- 현재 워크플로는 `main`에 `cron: '*/10 * * * *'` 등록, 수집 프로그램은 별도 연구 브랜치에 있음. 정확한 600초 간격은 GitHub Actions가 보장하지 않으며 실행이 아예 누락될 수도 있음.
- 성공 요건은 **서로 다른 예약 슬롯에서 최소 2회 `event=schedule` 실제 완료 + 누적 장부 변경/0점 결과 + GitHub 이슈 #2 댓글**까지 실증. `push`와 `workflow_dispatch`는 예약 성공 증빙으로 계산 금지.
- 시간 기준 감시: 각 한국시간 10분 슬롯과 실제 `run_id`, `event`, `status`, `new_originals_verified`, `new_adapted_displayable`, `total`을 대조. 실행 자체가 없으면 `MISSING_SCHEDULE_RUN`, 실행 실패는 `FAILED`, 정상 0점은 `ZERO_NEW`.
- GitHub 워크플로 미실행은 해당 워크플로가 스스로 댓글을 남길 수 없으므로, **독립 모니터**가 필요함. 현재 사용자가 연결한 ChatGPT 자동화는 최소 1시간 간격이므로 **최근 1시간의 미실행 슬롯 수와 신규 증가**를 보고. 10분마다 ChatGPT 알림이라고 주장 금지.
- GitHub 이슈 댓글 알림은 구독/알림설정과 GitHub 전달 상태에 따라 달라짐. 게시 성공과 푸시 수신은 다른 사실.

## 8. 무료 실행·용량·오류 복구

- GitHub Actions 한 작업: 최대 80건 검증, 200회 원본 다운로드 시도, 최대 12페이지·345초, API 제한 및 CPU/메모리 사용량에 따라 더 적을 수 있음. 무한 확대 금지.
- 현재 GitHub Actions 아티팩트 누적이 2GiB를 넘은 이력이 있어, 추가 저장은 자동 예산 검사로 차단. **검증 원본을 일시 다운로드한 것과 영구 확보는 별개**.
- 태블릿에서는 최대 8GiB 이미지 캐시, 1.5GiB 여유, 오래되거나 이미 노출된 파일 삭제 우선. **90일 재노출 방지 기록은 이미지 파일 정리 후에도 유지**. 현재 전시와 다음 2~4개 이미지는 캐시 정리 대상에서 보호.
- 저장 불가·배터리 부족·메모리/네트워크 오류면 실패 원인 기록, 정해진 횟수의 지수 백오프, 다음 예약시 재시도. 원본/장부 덮어쓰기 금지; 임시 파일을 먼저 검사한 뒤 원자적으로 교체.
- 유효한 새 이미지가 고갈되면 90일 전에 이전 작품을 강제로 재사용하지 말고 표시 가능 작품 부족 상태를 기록.

## 9. 단계별 검증 게이트 (실행 전 필수)

1. **G0 회복:** GitHub `schedule` 이벤트가 실제로 2회 이상 발생하는지 확인. 없으면 자동 지속 수집 완료 불가.
2. **G1 원본/변환 테스트:** 서로 다른 시대·기법·가로/세로/작은 해상도 이미지에 대해 디코딩·크롭 좌표·중심 누락·75% 면적·업스케일 품질·라이선스 검증. 0 중복 집계.
3. **G2 원격 정산:** `run_history.csv` 의 회차별 신규점 수 합 = 추가된 중복 제거 원본 ID 수; 누적 합계 일치. 누락 예약 슬롯도 정확히 표시.
4. **G3 Android 실물:** 갤럭시 탭 A7에서 실제 변환 JPEG 재디코딩, 화면별 영역 측정, 앱 복귀·네트워크 장애·재부팅 복구, 실제 8GiB 상한과 여유 공간 시험.
5. **G4 전시 운영:** 30초 교체, 90일 ID 유효성, 가로 30% 허용 전시, 잘못된 이미지 크롭 자동 폴백, 결제/인증 필요 없음 검증.

**현재 승인 결과:** G0~G4 전부 아직 통과 판정 불가. 문서 작성 및 기존 성공한 수집 `push`만으로 무인 운영·이미지 변환 엔진 완성이라고 주장하지 않음.
