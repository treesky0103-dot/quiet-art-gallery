# 고요한 미술관 · 안드로이드 태블릿 자동 명화 갤러리 v1.1

**상태: 1.1 개발 소스 및 자동화 모의 시험 결과. Android SDK가 없는 실행 환경이라 실제 APK 빌드와 안드로이드 실기기 검증은 미완료.**

## 확정 운영 조건

- 30초마다 작품 교체, 다음 이미지 1장 미리 로딩
- 70% 세로형, 30% 가로/정사각형 목표(적격 작품 부족 시 목표 비율 변동 가능)
- 마지막 감상에서 **90 × 24시간 이상** 지나야 같은 작품 재사용
- 매일 한국시간 10:00 전시 목록 갱신(앱이 열려 있으면 동작, 꺼져 있으면 다음 실행 때 처리)
- 회화·드로잉·판화 등 평면 그림만, 액자/전시실 사진과 조각·설치미술 제외
- 이미지 원본 비율 보존(`object-fit:contain`), 전시 화면엔 액자 UI/텍스트를 기본 표시하지 않음
- 공개 작품 API: Cleveland Art, Art Institute of Chicago, Metropolitan Museum
- APK에서 앱 관리 **이미지 파일 캐시 100MB 상한**, 100MB 초과 시 LRU 방식으로 약 80MB까지 자동 삭제
- 감상 기록 IndexedDB에 별도 저장(그림 파일과 분리); 최근 90일 이전 기록을 일별 정리
- 최근 90일 감상 기록 CSV **백업·복원** 제공. 반복된 GitHub Actions 디버그 APK 빌드의 서명이 달라 새 APK가 기존 설치판을 덮어쓰지 못하는 경우에도, 기록을 내보낸 뒤 새로 설치하고 복원할 수 있게 보강
- 앱 실행 중 화면 켜짐 유지, 몰입형 전체화면
- 광고, 가입, 신용카드, 서버, 유료 API 불필요. **전기료·인터넷 데이터 사용은 별도**

## 가장 쉬운 무료 APK 만들기 — GitHub Actions

GitHub 공개 저장소의 일반 GitHub Actions 실행 시간은 무료입니다. 가입한 GitHub 계정은 필요합니다(결제수단 등록은 요구하지 않는 무료 공개 저장소 방식).

1. GitHub에서 **새 공개(public) 저장소**를 만듭니다.
2. 이 폴더 안의 `.github`, `android-app`, `web`, `tests`, `README_KO.md`를 **저장소 루트에** 업로드합니다. `.github` 폴더도 누락하지 마세요.
3. 저장소의 **Actions → Build Gallery APK → Run workflow**를 선택합니다. (CI는 JavaScript 로직 테스트, 웹/Android 파일 일치 검사 뒤 APK 빌드를 시도합니다.)
4. 실행이 성공하면 해당 작업의 **Artifacts → QuietArtGallery-debug-APK**를 내려받습니다.
5. ZIP을 풀면 `app-debug.apk`가 있습니다. 이를 안드로이드 태블릿에 복사해 설치합니다.
6. 설치 권한 화면에서 **이 출처의 앱 설치 허용**을 사용자가 직접 선택합니다.
7. 이후 다시 빌드한 디버그 APK는 이전 디버그 APK와 서명이 다를 수 있습니다. **설정 → 감상 기록 백업 → 기존 앱 제거 → 새 APK 설치 → 감상 기록 복원** 순서를 따르세요. 백업하지 않고 앱을 제거하면 90일 기록을 잃을 수 있습니다.

**중요:** 이 클라우드 빌드 워크플로는 작성했지만 현재 환경에서 실행 검증하지 못했습니다. GitHub 저장소에 소스가 공개된다는 점도 고려하세요. APK 자체는 아직 포함되지 않습니다.

## Windows PC에서 직접 빌드

1. 공식 Android Studio를 무료 설치합니다. `android-app` 폴더를 **Open**으로 엽니다.
2. Gradle 8.9, Android SDK 플랫폼 35, JDK 17을 구성합니다. Android Studio가 필요한 SDK 다운로드 안내를 제공할 수 있습니다.
3. 프로젝트 Sync가 성공하면 **Build → Build Bundle(s) / APK(s) → Build APK(s)**를 실행합니다.
4. 성공 시 `android-app/app/build/outputs/apk/debug/app-debug.apk`가 생성됩니다.
5. 태블릿으로 복사해 설치합니다.

프로젝트는 표준 Gradle 소스이며 Gradle Wrapper JAR와 빌드 산출물은 이 배포본에 포함되지 않았습니다. 로컬 Android Studio 구성에 따라 외부에서 Gradle 8.9를 먼저 설치해야 할 수 있습니다.

## 앱 사용법

- 앱 실행 → Wi-Fi 연결 → 공개 미술관에서 새 작품 불러오기 → 30초 간격 전환
- 그림 화면 터치 → 상단 메뉴 → 일시정지 / 다음 그림 / 설정
- 설정 → 이미지 캐시 비우기 / 작품 목록 재조회 / 90일 감상 기록 CSV **백업 및 복원**
- 이전에 본 작품은 제한 만료 전 재생하지 않으며, 새 작품이 부족하면 마지막 그림을 유지합니다.
- 인터넷 단절 또는 기관 API 오류가 발생하면 캐시된 **마지막 작품**은 다시 표시할 수 있지만, 오프라인 상태에서 계속 새로운 작품이 전시되는 것은 보장하지 않습니다.
- 원래 갤러리 목적은 24시간 화면 전시이므로 앱을 항상 **전면에 열어 놓아야 합니다**. 기기 재부팅이나 강제 종료 뒤 자동 재실행은 포함되지 않습니다.

## v1.1 개선점

- 감상 기록 백업과 복원: CSV `key,shown_at` 포맷만 허용하고 날짜·작품 ID를 검증합니다. 만료된 90일 이전 기록과 미래 시각은 제외하며, 기존 기록이 더 최신이면 덮어쓰지 않습니다. 최대 CSV 128MB.
- 단일 다음 이미지 로딩 작업을 Promise로 공유하여, 수동 전환·자동 선로딩 충돌 중 동일 작업이 겹치는 문제를 줄였습니다.
- Github Actions 사전 핵심 로직 검사와 웹/Android 자산 파일 일치 검사를 추가했습니다. `setup-android@v4`로 업데이트했습니다.
- 작동 검증은 Chromium의 모의 미술관 이미지/응답만 사용했습니다. 실제 미술관 서버 이미지, APK 설치, 72시간 연속 구동은 아직 검증되지 않았습니다.

## 용량 자동 삭제 원칙

안드로이드 APK는 미술관 이미지 파일을 앱의 `cacheDir/gallery-images`에 저장합니다.

- `art-image` 경로로 이미지를 요청할 때 HTTPS와 허용된 미술관 이미지 도메인을 검증합니다.
- 이미 캐시된 이미지는 파일을 재사용합니다. 캐시 파일은 SHA-256(URL) 이름으로 관리합니다.
- 이미지 한 장당 최대 8MB, 앱 관리 이미지 캐시의 소프트 상한은 100MB입니다.
- 저장량이 상한을 초과하면 가장 오래 사용하지 않은 이미지부터 삭제해 80MB까지 줄입니다.
- `seen` DB(작품 ID·마지막 전시시각)는 이미지 캐시 폴더와 분리되며 캐시 삭제 시에도 보존합니다.

> 100MB는 앱이 관리하는 이미지 캐시의 상한입니다. APK 파일 크기, Android WebView의 별도 캐시, IndexedDB 기록은 이 수치에 포함되지 않습니다. 시스템 측 캐시까지 100MB 이내라고 주장하지 않습니다.

## 안전성 및 수급 한계

- 미술관 메타데이터로 2D 작품인지 필터링하고, CC0/퍼블릭 도메인으로 명시된 이미지만 선택합니다. 공개 이미지라 해도 모두 무조건 자유로운 것은 아닙니다.
- 실제 그림 이미지에 액자가 포함되는지 자동으로 **완벽하게 판단할 수 없습니다.** 1차 출시의 액자 제거는 작품 종류/소스 선택에 의존합니다. 정확한 프레임 제거를 보장하지 않으며 직접 미술관 이미지 검증이 필요합니다.
- 90일 동안 30초마다 중복 없이 전시하려면 총 259,200개의 서로 다른 적격 작품이 필요합니다. 이 소스 3곳만으로 해당 수를 충족한다는 검증은 없습니다.
- 미술관 서버가 접근을 차단하거나 응답 형식을 바꾸면 공급이 중단될 수 있습니다. API 변경 시 소스 코드를 업데이트해야 합니다.
- 각 기관의 API 호출 속도 제한 및 이용 약관을 준수해야 합니다. 앱은 네트워크 요청을 제한하지만 실서버 측 승인/성능 검증은 아직 없습니다.
- Android WebView와 외부 API의 실제 연결 및 연속 72시간 운영은 수행하지 않았습니다.
- APK 디버그 서명은 빌드마다 달라질 수 있습니다. 공개 GitHub 저장소에 개인 서명키를 올리면 안 됩니다. 정식 장기 운영을 위해서는 안전하게 보관한 개인 서명키로 릴리스 빌드하는 절차가 추가로 필요합니다.
- 신규 제공되는 이미지가 모두 현대미술인 것도 아니고, 2D 현대미술의 공개 이용 가능 수량은 제한적입니다.

## 파일 구성

```
.github/workflows/build-apk.yml       무료 GitHub Actions APK 빌드 워크플로 (미실행)
android-app/                           Android Studio Java·Gradle 프로젝트
  app/src/main/java/com/gallery/kiosk/MainActivity.java
  app/src/main/assets/                 웹앱과 동일 화면 코드
web/                                   Chrome/PWA용 웹 버전
  index.html, style.css, core.js, app.js, manifest.webmanifest, sw.js
tests/                                 Node 핵심 로직 시험 + Chromium DOM 모의 시험
```
